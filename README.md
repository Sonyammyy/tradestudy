# 무역노트 · 국제무역사 1급 스터디 웹사이트

국제무역사 1급(한국무역협회 주관)을 준비하면서 직접 쓰는 학습용 홈페이지입니다.
개념 정리, 인코텀즈, 결제방식 흐름도, 오답노트, 합격 시뮬레이터를 각각 독립된 페이지로 나누고, 홈 화면에서 오늘 공부할 내용과 도구를 한눈에 볼 수 있게 만듭니다.

- **기술 스택**: HTML · CSS · JavaScript (프레임워크 없이 순수 구현)
- **개발 환경**: VS Code + Live Server 확장
- **목표 시험**: 제67회 국제무역사 1급 · 2026년 11월 28일(토) 09:30–11:30

## 3. 디자인 시스템

### 3-1. 컬러

지정 팔레트 5색을 그대로 메인으로 씁니다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--navy` | `#2A5078` | 메인. 제목, 채운 버튼, 활성 탭, 흐름도 화살표, 링크 |
| `--steel` | `#6587A5` | 보조. 아이콘, 보조 버튼 외곽선, 차트 2차 계열, 호버 |
| `--white` | `#FFFFFF` | 패널·카드 배경 |
| `--gray` | `#848996` | 메타 정보, 날짜, 캡션, 비활성 텍스트 |
| `--mist` | `#DBE4EB` | 페이지 배경, 구분선, 입력창 배경, 칩 배경 |

팔레트에서 파생한 값 (새 색을 추가하지 않고 섞어서 만듭니다):

```css
:root {
  --navy: #2A5078;
  --steel: #6587A5;
  --white: #FFFFFF;
  --gray: #848996;
  --mist: #DBE4EB;

  /* 파생 */
  --ink: color-mix(in srgb, var(--navy) 70%, #000);          /* 본문 텍스트 */
  --tint-1: color-mix(in srgb, var(--steel) 10%, var(--white)); /* 타일 A */
  --tint-2: color-mix(in srgb, var(--steel) 18%, var(--white)); /* 타일 B */
  --tint-3: color-mix(in srgb, var(--mist) 70%, var(--white));  /* 타일 C */
  --line: var(--mist);

  /* 상태색 (정답/오답/경고 표시에만 사용) */
  --ok: #2E7D5B;
  --bad: #C0392B;
  --warn: #B7791F;
}
```

**Pretendard** 하나로 통일합니다. 숫자가 줄 맞춰야 하는 곳(D-day, 점수, 날짜)에는 `font-variant-numeric: tabular-nums`.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css">
```

```css
body { font-family: "Pretendard Variable", Pretendard, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif; }
```

### 3-4. 공통 컴포넌트

- `btn--primary`: `--navy` 배경 + 흰 글씨 pill (레퍼런스의 검정 버튼 자리)
- `btn--outline`: 흰 배경 + `--mist` 외곽선 pill
- `chip`: `--mist` 배경, 클릭 가능한 추천 질문/필터
- `tile`: 아이콘 + 라벨 + 오른쪽 원형 `>` 버튼, `--tint-*` 배경
- `panel`: 흰 배경, `--r-panel`, 상단에 제목 바 + 하단 구분선
- `badge-dday`: `--navy` 배경 pill, `D-51` 형식

## 5. 페이지별 명세

### 5-1. 홈 `index.html`

레퍼런스와 같은 3분할 레이아웃. 데스크톱 기준 `grid-template-columns: 1fr 1.9fr 1fr`, 1024px 이하에서 좌측 패널 접힘, 768px 이하에서 세로 1열.

**좌측 · 학습 목차**
- 전체 진행률 바 (체크한 개념 수 / 전체 개념 수)
- 개념 검색창
- `전체 선택` 체크
- W1–W7 목록. 각 행: 주차 번호, 제목, 기간, 완료 체크박스. 이번 주는 `--tint-2` 배경으로 강조

**중앙 · 오늘의 학습**
- 주차 아이콘 배지
- 큰 제목: 이번 주 주제 (예: "무역계약 기초 · 인코텀즈 2020")
- 메타: `W1 · 10.08–10.14 · 필수 개념 14개`
- 요약 문단: 이번 주에 반드시 알아야 할 개념을 **굵게** 표시
- 버튼: `복습 완료` · `개념노트로 이동` · `오답 추가`
- 추천 질문 칩 3–4개 (예: "CIF와 CIP의 보험 조건 차이는?"). 클릭하면 개념노트의 해당 항목으로 이동
- 하단 입력창: 개념 빠른 검색

**우측 · 학습 스튜디오**
- 상단 배너: 원서접수 상태 (`접수까지 25일` / `접수 중 · 11.15 마감`), 닫기 버튼
- 2열 타일: 개념노트, 인코텀즈, 결제 흐름도, 합격 시뮬레이터, 오답노트, 암기카드, 시험정보
- 아래 영역: 최근 오답 3개 미리보기
- 하단 고정 버튼: `오답 추가`

### 5-2. 개념노트 `study.html`

- 상단에 7주 타임라인 (가로 스크롤 스텝퍼). 오늘 날짜 위치 표시
- 주차 탭을 누르면 해당 주의 개념 카드 목록
- 개념 카드: 개념명 · 한 줄 정의 · 상세 설명(펼치기) · 시험 포인트 · 관련 조항 · `외웠어요` 체크 · `오답노트에 추가`
- 오른쪽 사이드: 이번 주 진행률, 주차 체크리스트
- 콘텐츠는 [6장](#6-학습-콘텐츠-범위-7주-개념-목록) 목록 전체를 `js/data/concepts.js`에 담습니다

### 5-3. 인코텀즈 `incoterms.html`

과목 그룹(E·F·C·D)이 아니라 **운송방식 기준으로 나눕니다.**

| 구분 | 규칙 |
| --- | --- |
| 해상 및 내수로 운송 전용 (4) | FAS · FOB · CFR · CIF |
| 모든 운송방식 (7) | EXW · FCA · CPT · CIP · DAP · DPU · DDP |

- 상단 토글: `해상 전용 4` / `모든 운송방식 7`
- 규칙 선택 시 **분기점 트랙**: 매도인 공장 → 수출통관 → 운송인 인도·선측 → 본선 적재 → 주운송 → 목적지 도착 → 양하 → 수입통관
  - 매도인 비용 부담 구간은 `--navy` 선, 위험 이전 지점은 깃발 마커
  - C 규칙처럼 위험과 비용 분기점이 다르면 두 지점을 모두 표시
- 상세 카드: 위험 이전 시점, 운송계약 주체, 보험 의무, 수출·수입 통관 주체, 적재·양하 의무, 시험 포인트
- 비교표: 11개 규칙 × 항목 (가로 스크롤)
- 2020 개정사항 박스 (6장 W1 참고)

### 5-4. 결제방식 `payment.html`

독립 페이지. 상단 탭으로 결제방식 선택, 아래에 설명 → 흐름도 → 단계 상세 순서로 세로 배치합니다.

**탭 구성**
1. 송금방식 · 사전송금 (CWO / CIA)
2. 송금방식 · 사후송금 (O/A / COD / CAD)
3. 추심 · D/P (지급인도)
4. 추심 · D/A (인수인도)
5. 신용장 · 일람출급 (At Sight L/C)
6. 신용장 · 기한부 (Usance L/C) – 하위 토글: Shipper's Usance / Banker's Usance

**각 탭 구성**
- 개요: 정의, 적용 규칙(URC 522 / UCP 600 등), 수출자 위험도 5단계, 수입자 부담, 언제 쓰는지, 장단점
- **인터랙티브 흐름도**
  - 참여자 전원을 세로 레인(swimlane)으로 배치
  - 단계마다 번호 붙은 화살표 (① ② ③ …)
  - 화살표 또는 번호를 클릭하면 오른쪽(모바일은 하단 시트)에 단계 상세 표시
  - `이전` / `다음` 버튼과 `자동 재생`으로 순서대로 따라가기
  - 현재 단계의 화살표는 `--navy`, 지난 단계는 `--steel`, 남은 단계는 `--mist`
- **단계 상세 패널**: 누가 → 누구에게, 무엇을 하는지, **필요한 서류**, 필요한 조건·확인사항, 관련 조항, 시험 포인트
- 하단 비교표: 6개 결제방식 × (은행 지급확약 여부, 서류 인도 시점, 대금 지급 시점, 수출자 위험, 수입자 자금부담, 적용 규칙)

흐름도는 SVG로 그리고, 단계 데이터는 `js/data/payments.js`에 둡니다. 데이터 내용은 [7장](#7-결제방식-흐름도-데이터-명세).

### 5-5. 오답노트 `notes.html`

작은 카드가 아니라 **전용 페이지**로 크게 만듭니다.

## 6. 학습 콘텐츠 범위 (7주 개념 목록)

기간은 2026.10.08 시작, 11.28 시험 기준입니다. 아래 항목은 모두 `concepts.js`에 개념 카드로 들어갑니다.

### W1 · 10.08–10.14 · 무역계약 기초 · 인코텀즈 2020 `무역계약`

**무역계약의 성립**
- 무역계약의 법적 성질: 낙성계약, 쌍무계약, 유상계약, 불요식계약
- 청약(Offer)과 청약의 유인(Invitation to offer) 구분
- 청약의 종류: 확정청약(Firm offer), 자유청약(Free offer), 반대청약(Counter offer), 조건부청약
- 승낙: 경상의 원칙(Mirror image rule), 침묵은 승낙이 아님, 승낙의 효력발생 시기 (CISG 도달주의)
- 일반거래조건협정서

**8대 거래조건**
- 품질조건: 견본·상표·규격·명세서 매매, 표준품 매매 (FAQ, GMQ, USQ), 품질 결정시기 (선적품질 / 양륙품질, TQ·RT·SD)
- 수량조건: 수량 단위, 과부족 용인조항 (M/L clause)
- 가격조건: 인코텀즈 연계
- 선적조건: 선적시기, 분할선적, 환적
- 보험조건 / 결제조건
- 포장조건과 화인(Shipping marks)
- 클레임·중재조건

**인코텀즈 2020**
- 11개 규칙: 해상·내수로 전용 4개 (FAS, FOB, CFR, CIF), 모든 운송방식 7개 (EXW, FCA, CPT, CIP, DAP, DPU, DDP)
- 규칙별 인도 지점, 위험 이전 시점, 비용 분기점
- C 규칙은 위험 이전 지점과 비용 분기점이 다름 (2개의 분기점)
- 2020 주요 개정: DAT → DPU 명칭 변경, CIP 최소 부보조건 ICC(A)로 상향 (CIF는 ICC(C) 유지), FCA 본선적재 표기 B/L 발행 지시, 매도인·매수인 자신의 운송수단 사용 허용, 보안 관련 의무·비용 배분 명시, A1–A10 / B1–B10 구조
- 컨테이너 화물에는 FOB 대신 FCA, CIF 대신 CIP 권장
- 인코텀즈가 다루지 않는 것: 소유권 이전, 계약위반 구제, 대금지급 방법, 분쟁해결

### W2 · 10.15–10.21 · CISG · 운송 · 적하보험 `무역계약`

**CISG (국제물품매매계약에 관한 UN협약, 1980 비엔나 / 한국 2005 발효)**
- 적용 범위: 영업소가 서로 다른 체약국에 있는 당사자 간 물품매매
- 적용 제외: 개인·가정용 매매, 경매, 강제집행, 유가증권·통화, 선박·항공기, 전기
- 계약의 성립 (청약·승낙 조항)
- 본질적 계약위반 (Fundamental breach, 제25조)
- 매도인 의무: 물품 인도, 서류 교부, 계약 적합성
- 매수인 의무: 대금 지급, 인도 수령
- 매수인의 구제: 특정이행 청구, 대체물 인도 청구(본질적 위반 시), 하자보완 청구, 부가기간 지정, 계약 해제, 대금 감액, 손해배상
- 매도인의 구제: 이행 청구, 부가기간 지정, 계약 해제, 물품명세 확정, 손해배상
- 위험의 이전 (제66–70조), 손해배상 범위와 예견가능성 (제74조), 손해경감 의무 (제77조), 면책 (제79조)

**운송**
- 정기선(개품운송)과 부정기선(용선운송)
- 용선계약: 항해용선, 정기용선, 나용선 / 정박기간(Laytime), 체선료(Demurrage), 조출료(Despatch money)
- 운임 할증료: BAF, CAF, THC 등
- 컨테이너 운송: FCL / LCL, CY / CFS
- 선하증권(B/L)의 기능: 화물수령증, 운송계약의 증거, 권리증권
- B/L 종류: 선적 / 수취, 무사고 / 사고, 지시식 / 기명식, 기간경과(Stale), 제3자, 통선하증권, Surrendered B/L
- 비유통 운송서류: 해상화물운송장(Sea Waybill), 항공화물운송장(AWB)
- 수입화물선취보증서(L/G)
- 복합운송과 복합운송인 (FIATA FBL)
- 해상운송 국제규칙: 헤이그(1924), 헤이그-비스비(1968), 함부르크(1978), 로테르담(2008) / 책임한도와 항해과실 면책 비교
- 항공운송: 몬트리올 협약, AWB

**적하보험**
- 해상보험 기본원칙: 피보험이익, 최대선의, 담보(Warranty), 근인주의
- 해상손해: 전손 (현실전손, 추정전손), 분손 (단독해손, 공동해손), 비용손해 (손해방지비용, 구조비)
- 협회적하약관 ICC(A), ICC(B), ICC(C)의 담보범위 차이
- 부가약관: 전쟁약관, 동맹파업약관
- 면책위험: 피보험자의 고의적 불법행위, 통상의 누손·자연소모, 포장 불충분, 지연 등
- 보험기간: 창고 간 약관 (Warehouse to warehouse)
- 보험증권과 보험증명서

### W3 · 10.22–10.28 · 무역결제 · 신용장 `무역결제`

**송금방식**
- T/T(전신송금), M/T(우편송금), D/D(송금수표)
- 사전송금: CWO, CIA / 사후송금: COD, CAD, O/A(청산계정)

**추심방식 (URC 522)**
- 당사자: 추심의뢰인(수출자), 추심의뢰은행, 추심은행, 제시은행, 지급인(수입자)
- D/P(지급인도)와 D/A(인수인도)의 서류 인도 시점 차이
- 화환추심과 무화환추심
- 은행은 지급을 보증하지 않음

**신용장 (UCP 600)**
- 신용장의 독립성·추상성 원칙, 서류거래 원칙
- 당사자: 개설의뢰인, 개설은행, 수익자, 통지은행, 확인은행, 지정은행(지급·인수·매입), 상환은행
- 종류: 확인신용장, **일람출급(At Sight) / 기한부(Usance)**, 지급·연지급·인수·매입 신용장, 양도가능신용장, 회전신용장, 보증신용장(Standby, ISP98), 구상무역신용장(Back-to-Back), 내국신용장(Local L/C), 선대신용장(Red clause)
- UCP 600 모든 신용장은 취소불능
- Usance 구분: Shipper's Usance (수출자가 신용 공여) / Banker's Usance (은행이 신용 공여, 수출자는 일람불처럼 즉시 수령)
- 주요 조항
  - 제2조 정의 (일치하는 제시)
  - 제3조 해석 (on or about = 전후 5일, to·until·from은 해당 일 포함)
  - 제14조 서류심사 기준 (5은행영업일, 선적 후 21일 이내 제시)
  - 제16조 하자서류 거절 통지
  - 제18조 상업송장
  - 제20조 선하증권
  - 제28조 보험서류 (최소 110%, 선적일보다 늦은 일자 불가)
  - 제29조 유효기일 연장 (은행 휴무)
  - 제30조 과부족 (about ±10%, 수량 ±5%)
  - 제31조 분할선적 / 제32조 할부선적
  - 제36조 불가항력
  - 제38조 양도 (1회 한정)
- 하자서류 처리: L/G 네고, 유보부 매입, 추심 전환

### W5 · 11.05–11.11 · 무역규범 `무역규범`

**대외무역법**
- 무역의 정의: 물품, 대통령령이 정하는 용역, 전자적 형태의 무체물
- 수출입공고, 통합공고, 전략물자고시
- 수출입 승인과 전략물자 수출허가
- 외화획득용 원료·물품 수입
- 특정거래형태: 위탁판매, 수탁판매, 중계무역, 중개무역, 외국인도수출, 외국인수수입, 임대차, 무환수출입
- 원산지 판정기준: 완전생산기준, 실질적 변형기준 (세번변경, 부가가치, 주요공정)
- 원산지 표시 의무와 방법

**관세법 · 통관**
- 과세요건 4가지: 과세물건, 납세의무자, 과세표준, 세율
- 과세물건 확정시기와 적용법령 (수입신고 시점)
- 관세평가 6가지 방법: 거래가격(가산·공제요소), 동종·동질물품, 유사물품, 국내판매가격, 산정가격, 합리적 기준
- 세율 적용 우선순위 (덤핑방지·상계·보복·긴급관세 등 → 국제협력·편익관세 → 조정·할당·계절관세 → 일반특혜관세 → 잠정세율 → 기본세율, FTA 협정세율은 FTA특례법에 따라 우선 적용)
- 수출신고와 신고수리 후 선적 기한
- 수입신고 시기: 출항 전, 입항 전, 하선 전, 보세구역 도착 전, 보세구역 반입 후 / 반입 후 30일 이내 신고 (위반 시 가산세)
- 신고수리 전 반출, 수입신고 전 즉시반출
- 보세구역: 지정보세구역 (지정장치장, 세관검사장), 특허보세구역 (보세창고, 보세공장, 보세전시장, 보세건설장, 보세판매장), 종합보세구역
- 보세운송

**관세환급**
- 관세환급특례법: 개별환급과 간이정액환급
- 환급 요건과 청구기한 (수출신고 수리일부터 2년)
- 소요원재료와 과다환급

**FTA**
- 원산지결정기준: 완전생산기준, 세번변경기준 (CC · CTH · CTSH), 부가가치기준, 가공공정기준
- 보충적 기준: 미소기준(De minimis), 누적기준, 직접운송원칙
- 원산지증명 방식: 자율발급과 기관발급, 인증수출자
- 원산지 사후검증, 협정관세 적용 신청

### W6 · 11.12–11.18 · 무역영어 `무역영어` · 원서접수 마감 11.15

- 거래 단계별 무역서신: 신용조회, 거래제의, 청약, 반대청약, 주문, 승낙, 신용장 개설 통지, 선적 통지, 클레임

### 참여자 사전

| key | 이름 | 다른 이름 |
| --- | --- | --- |
| `exporter` | 수출자 | 수익자(L/C), 추심의뢰인(추심) |
| `importer` | 수입자 | 개설의뢰인(L/C), 지급인(추심) |
| `remittingBank` | 송금은행 | 수입자 거래은행 |
| `payingBank` | 지급은행 | 수출자 거래은행 |
| `issuing` | 개설은행 | Issuing Bank |
| `advising` | 통지은행 | Advising Bank |
| `confirming` | 확인은행 | 확인신용장일 때만 |
| `negotiating` | 매입은행 | 지정은행 |
| `accepting` | 인수은행 | Banker's Usance |
| `reimbursing` | 상환은행 | Reimbursing Bank |
| `collectingRemit` | 추심의뢰은행 | Remitting Bank |
| `collecting` | 추심은행·제시은행 | Collecting / Presenting Bank |
| `carrier` | 운송인 | 선사·항공사·포워더 |
| `insurer` | 보험회사 | CIF·CIP일 때 |

### 결제방식별 단계 초안

**① 사전송금 (CWO · CIA)**
1. 매매계약 체결 (결제조건: 선적 전 송금) – 계약서, P/I
2. 수입자 → 송금은행: 송금 신청 – 지급신청서, 계약서·P/I, 외화 대금
3. 송금은행 → 지급은행: 송금 지시 – SWIFT MT103
4. 지급은행 → 수출자: 입금 통지 – 입금통지서
5. 수출자 → 운송인: 선적 – 수출신고필증, B/L 수령
6. 수출자 → 수입자: 선적서류 직접 송부 – B/L, 상업송장, 포장명세서, 원산지증명서
7. 수입자 → 운송인: B/L 제시 후 화물 인수

**② 사후송금 (O/A · COD · CAD)**
1. 매매계약 체결 (결제조건: 선적 후 일정 기간 내 송금 / 도착 시 / 서류 인도 시)
2. 수출자 → 운송인: 선적 – B/L
3. 수출자 → 수입자: 선적서류 직접 송부 (CAD는 수출국 대리인 통해 서류와 대금 교환)
4. 수입자 → 운송인: 화물 인수
5. 수입자 → 송금은행: 만기에 송금 신청 – 지급신청서, 상업송장
6. 송금은행 → 지급은행: SWIFT MT103
7. 지급은행 → 수출자: 입금 (O/A 채권은 은행에 매각해 조기 현금화 가능)

**③ 추심 D/P · ④ 추심 D/A (URC 522)**
1. 매매계약 체결 (결제조건: D/P 또는 D/A, D/A는 만기일 명시)
2. 수출자 → 운송인: 선적 – B/L 수령
3. 수출자 → 추심의뢰은행: 추심 의뢰 – 추심의뢰서, 환어음 (D/P: 일람출급 / D/A: 기한부), B/L, 상업송장, 포장명세서, 보험증권
4. 추심의뢰은행 → 추심은행: 서류 송부 – 추심지시서 + 서류 일체
5. 추심은행 → 수입자: 서류 도착 통지 및 제시
6. **D/P**: 수입자 → 추심은행 대금 지급 / **D/A**: 수입자 환어음 인수(서명)
7. 추심은행 → 수입자: 선적서류 인도
8. 수입자 → 운송인: B/L 제시, 화물 인수
9. (D/A만) 만기일에 수입자 → 추심은행 대금 지급
10. 추심은행 → 추심의뢰은행: 대금 송금
11. 추심의뢰은행 → 수출자: 대금 지급
- 핵심: 은행은 지급을 보증하지 않음. D/A는 대금 없이 서류가 나가므로 수출자 위험이 D/P보다 큼

**⑤ 일람출급 신용장 (At Sight L/C)**
1. 매매계약 체결 (결제조건: 일람출급 취소불능 신용장)
2. 수입자 → 개설은행: 개설 신청 – 개설신청서, 외국환거래약정서, P/I, 담보
3. 개설은행 → 통지은행: 신용장 발행 – SWIFT MT700
4. 통지은행 → 수출자: 신용장 통지 – 진위 확인 후 통지서
5. 수출자: 신용장 조건 검토, 필요 시 조건변경 요청 (MT707)
6. 수출자 → 운송인 / 보험회사: 선적 및 부보 – B/L, 보험증권 (CIF·CIP)
7. 수출자 → 매입은행: 매입(네고) 신청 – 일람출급 환어음, 상업송장, B/L, 포장명세서, 보험증권, 원산지증명서, 기타 신용장 요구 서류
8. 매입은행: 서류심사 후 매입대금 지급 (환가료 공제)
9. 매입은행 → 개설은행: 서류 송부 / 상환은행 → 매입은행: 상환
10. 개설은행: 서류심사 (최장 5은행영업일), 일치하면 상환 확정
11. 개설은행 → 수입자: 서류 도착 통지, 수입자 대금 결제 후 서류 인도
12. 수입자 → 운송인: B/L 제시, 화물 인수 (서류가 늦으면 L/G로 선취)

**⑥ 기한부 신용장 (Usance L/C)**
- 1–7단계는 At Sight와 같고, 환어음이 **기한부(예: 일람 후 90일)**
- **Shipper's Usance**
  8. 매입은행 → 개설은행: 서류 송부
  9. 개설은행: 환어음 인수 (인수 통지)
  10. 개설은행 → 수입자: 서류 인도 (수입자는 만기에 결제)
  11. 만기일: 수입자 → 개설은행 결제, 개설은행 → 매입은행 → 수출자 대금 지급
  - 수출자가 만기까지 신용 공여. 인수 후 할인 받으면 할인료는 수출자 부담
- **Banker's Usance**
  8. 매입은행: 수출자에게 즉시 대금 지급 (수출자 입장에선 일람불과 같음)
  9. 인수은행(또는 개설은행)이 환어음 인수 후 매입은행에 할인 지급
  10. 개설은행 → 수입자: 서류 인도
  11. 만기일: 수입자 → 개설은행 결제 → 인수은행 상환
  - 은행이 신용 공여. 할인료·인수수수료는 수입자 부담

> 각 단계의 서류·조항은 구현 단계에서 교재와 대조해 확정합니다.

## 9. 데이터 저장 방식

서버 없이 브라우저 `localStorage`에 저장합니다. 키는 `trade:` 접두사로 통일합니다.

| 키 | 내용 |
| --- | --- |
| `trade:planChecks` | 주차·개념별 완료 체크 |
| `trade:wrongNotes` | 오답노트 배열 |
| `trade:mockScores` | 모의고사 점수 기록 |
| `trade:flashcards` | 카드별 외움 상태 |
| `trade:prefs` | 마지막 선택 탭, 배너 닫힘 여부 |

```js
// 오답노트 항목 형태
{
  id: "1728372000000",
  subject: "무역결제",       // 무역규범 | 무역결제 | 무역계약 | 무역영어
  week: 3,
  topic: "D/A 서류 인도 시점",
  question: "",
  myAnswer: "",
  answer: "",
  reason: "지급과 인수를 헷갈림",
  concept: "D/A는 환어음 인수만으로 서류 인도",
  status: "review",          // review | again | done
  wrongCount: 1,
  createdAt: "2026-10-08",
  updatedAt: "2026-10-08"
}
```

브라우저 데이터를 지우면 기록이 사라지므로 오답노트 페이지에 JSON 내보내기·불러오기를 둡니다.
